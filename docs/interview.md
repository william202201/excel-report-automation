## 三分钟演示

1. 打开两份 `examples/input`，展示字段、列序和表头差异。
2. 运行 `python -m excel_report demo`，展示输入行数对账。
3. 打开 HTML 总览和 Excel，展示有效数据、月度汇总及图表。
4. 打开问题清单，按文件/表/行定位一条金额错误及一组冲突订单。
5. 修改一份副本的地区别名，扩展配置后重跑，说明数据契约如何演进。

## 面试重点

- 为什么不简单 `concat + drop_duplicates`？字段和单位必须先统一；同一业务键内容冲突要显式处理。
- 为什么用 Decimal 和整数分？避免二进制浮点误差影响金额校验与汇总。
- 为什么不把缺失字段都填 0？缺失与真实 0 含义不同，静默填充会掩盖数据问题。
- 如何确认没丢数据？输入=有效+隔离+重复，且每条保留来源坐标。
- 是原生透视表吗？是 pandas 透视汇总结果及 Excel 原生图表，刷新靠重新运行。
- 后续怎么扩展？组合业务键、退货口径、Parquet 分区/数据库、增量处理；需另做需求和规模验证。
